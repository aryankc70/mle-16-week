Chapter 1 — Session 1: What Is ML? Why Use It? Applications

Key definition: ML = program learns from Experience (E) w.r.t. Task (T) and Performance measure (P), if performance on T improves with E.
Non-example: more data ≠ learning, unless some T/P pair actually improves.
When to use ML: rule-lists that need constant upkeep; no known algorithm exists; fluctuating environments; need for data-mining insight.
When NOT to: if a small stable rule set solves it reliably — don't add ML overhead.
Heuristic to carry forward: input type × output type → technique family.

Chapter 1 — Session 2: Training Supervision + Batch vs. Online Learning

Supervised: labeled data. Classification predicts a category, regression predicts a number. Logistic regression outputs a probability, which is why it can act like a regression model but get used for classification.
Unsupervised: no labels. Four tasks: clustering, visualization/dimensionality reduction (merging correlated features = feature extraction), anomaly vs. novelty detection (novelty detection needs a training set with zero examples of what it's later supposed to flag as novel), and association rule learning.
Semi-supervised: mostly unlabeled data, a handful of labels. Usually just clustering + labeling each cluster once (Google Photos: cluster faces, you name each person once).
Self-supervised: gets its own category because it generates labels from the data itself (mask part of an image, train the model to reconstruct it). Same training mechanics as supervised learning. This is how LLMs get pretrained before fine-tuning.
Reinforcement learning: agent, environment, action, reward, policy. AlphaGo learned via RL, then had learning turned off during the actual match — offline application of a learned policy.
Batch learning: trains on everything at once, offline. Decays over time (data drift/model rot) — fixed by automating retraining, not by switching away from batch.
Online learning: incremental updates, enables out-of-core learning on data too big for memory. Learning rate trade-off: too high → catastrophic forgetting; too low → slow, but more robust to noise.
Naming trap: "online" doesn't mean "live in production," and "batch" here isn't the same "batch" as mini-batches in SGD.
